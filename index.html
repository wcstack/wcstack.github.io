v2.3.0 $recursion

Depth belongs to the data

What if one getter covered every level of a tree?

nodes.*.children.*.total has exactly two wildcard levels, and nothing about it stretches to three when the tree grows a level. $recursion: { "nodes.*": "children.*" } declares where the shape repeats — an anchor and the sub-path that descends one level — and ** then stands for “however deep this is”. One definition covers every depth: get "nodes.**.total"() reads this["nodes.**.value"] and folds its direct children, and the same formula is the totals at depth 1 and depth 12. $getAll(path, []) unions every depth depth-first, so treeTotal is a one-liner over a forest whose shape nothing in the code knows; $setAll(path, [], value) broadcasts one value to every node. The declaration is what gives ** a meaning at all — with no $recursion, it is not a path character, so the notation can never quietly slide into a descendant search.

nodes.*.children.*.totalのワイルドカードはちょうど2段で、木が1段伸びても3段には届かない。$recursion: { "nodes.*": "children.*" }は形が繰り返される場所を宣言する — アンカーと、1段降りる部分パス — そして**が「ここが何段であろうと」を表す。定義1つがすべての深さを覆う: get "nodes.**.total"()はthis["nodes.**.value"]を読んで直下の子を畳み込み、同じ式が深さ1の合計でも深さ12の合計でもある。$getAll(path, [])は全深さを深さ優先で連結するので、treeTotalは形をコードが知らない森に対する1行になる。$setAll(path, [], value)は1つの値を全ノードへ配る。**に意味を与えるのは宣言そのものだ — $recursionが無ければ**はパスの文字ですらないので、この記法が子孫検索へ黙って滑り込むことはありえない。

  • Anchor → Repeating Sub-path
  • One Getter, Every Depth
  • [] Unions the Whole Tree
  • No Declaration, No **
v2.3.0 **

Bound, or unioned

What if a depth variable read like a loop index?

** is a variable over depth, and context decides whether it is bound or unioned — the same split * already has between “the current row” and “every row”. In a getter key and in reads inside it, ** is bound to the depth being evaluated; $getAll with indexes omitted stays at that depth and expands only the wildcards after it; $getAll(path, []) unions every depth. That split is the whole game for aggregation: the omitted form sums the direct children, so each total folds its own subtree exactly once. Reach for [] inside the same getter and it asks for itself — you get wcs/getter-cycle, not a wrong number. The quiet mistake is the one made from outside: unioning an aggregate counts every grandchild once inside its parent’s total and again as an element. Union the raw values, or add up the roots. Whether an aggregate double-counts is not decidable from the path string, so no diagnostic claims to catch it.

**は深さについての変数で、束縛されるか連結されるかは文脈が決める — *がすでに持つ「現在の行」と「すべての行」の対比と同じだ。getterのキーとその内側の読みでは、**は評価中の深さに束縛される。インデックスを省いた$getAllはその深さに留まり、**より後ろのワイルドカードだけを展開する。$getAll(path, [])は全深さを連結する。集計ではこの対比がすべてだ: 省略形は直下の子を合計するので、各totalは自分の部分木をちょうど1回だけ畳み込む。同じgetterの中で[]に手を伸ばせば自分自身を要求することになり、間違った数ではなくwcs/getter-cycleが返る。静かな間違いは外から犯すほうだ: 集計値を連結すると、孫は親のtotalの中で1回、連結の要素としてもう1回数えられる。生の値を連結するか、根を足し合わせること。集計が二重計上かどうかはパス文字列からは決定できないので、これを捕まえると称する診断は無い。

  • Getter Key Binds the Depth
  • Omitted: This Depth
  • []: Every Depth, Pre-order
  • Double-counting Stays Yours
v2.3.0 wcs/recursion-*

The engine never sees a **

What if a new notation cost the core nothing?

** is authoring notation only. Reading a concrete path materializes the accessor for that depth on demand, one per depth actually touched, and everything downstream — PathInfo, the dependency graph, $1…$n, $resolve, the list diff — still sees an ordinary fixed-arity path. That invariant is kept by refusing, loudly, everything it cannot express. At declaration time: a second anchor, mutual recursion, a recursive setter, a ** getter naming the structure (get "nodes.**.children"() would hide the real child list at every depth), two getters expanding to one concrete path. At write time: anything targeting a recursive getter or its concrete expansions (wcs/recursion-readonly, before or after that depth exists), a broadcast at the structure itself (wcs/recursion-structural-write), a mapper or a non-empty prefix. And a bound ** read where no depth exists is wcs/recursion-context, never a guess at which node you meant. The editor and wcs-validate report every statically decidable form under the same codes, and stay silent where the declaration cannot be read statically.

**は記述上の記法にすぎない。具体的なパスを読むとその深さのアクセサが必要に応じて実体化され、実際に触れた深さの分だけ作られる。その下流 — PathInfo、依存グラフ、$1…$n、$resolve、リスト差分 — が見るのは相変わらず固定アリティの普通のパスだ。この不変条件は、表現できないものを大声で拒むことで守られる。宣言時には: 2つ目のアンカー、相互再帰、再帰的なsetter、構造を名指しする**getter(get "nodes.**.children"()は全深さで本物の子リストを隠してしまう)、同じ具体パスに展開される2つのgetter。書き込み時には: 再帰getterやその具体展開を狙うもの(wcs/recursion-readonly、その深さが実体化済みかどうかに関わらず)、構造そのものへのブロードキャスト(wcs/recursion-structural-write)、mapperや空でない前置インデックス。そして深さの無い場所で束縛形の**を読めばwcs/recursion-contextであって、どのノードのつもりかの推測ではない。エディタとwcs-validateは静的に判定できる形をすべて同じコードで報告し、宣言が静的に読めない場所では黙る。

  • Materialized Per Depth
  • Fixed Arity Downstream
  • Refused, Never Reinterpreted
  • Lint Uses the Same Codes
v2.3.0 one ledger

A list nothing rendered

What if an aggregate stopped depending on being displayed?

The baseline that $getAll and the dependency walk compare against used to be written only when a for rendered the list. So a structural write to a list nothing rendered — a sort, an insert, a parent re-assignment — minted a fresh ListIndex generation while the child ledgers kept pointing at the old one. The aggregate over that list went permanently stale, or threw ListIndexes not found, and the fix was the absurd one: render the list somewhere to make the number correct. The baseline now lives in a state-owned ledger shared by reads, rendering and the dependency walk, committed at the end of each update batch. A recursive $setAll commits what it observed for the same reason. Rendering is no longer a prerequisite for a correct read — which is also what makes an aggregate over a deep tree trustworthy when only the top level is on screen.

$getAllと依存の走査が比較するベースラインは、これまでforがそのリストを描画したときにだけ書かれていた。つまり、どこにも描画されていないリストへの構造的な書き込み — ソート、挿入、親ごとの再代入 — は新しいListIndex世代を作り、子の台帳は古い世代を指したままになる。そのリストに対する集計は永久に古びるか、ListIndexes not foundを投げた。そして直し方は馬鹿げていた: 数を正しくするためにリストをどこかに描画する。ベースラインはいま、読み・描画・依存走査が共有するstate所有の台帳に置かれ、更新バッチの終わりにコミットされる。再帰的な$setAllも同じ理由で観測結果をコミットする。正しい読みのために描画は前提ではなくなった — 深い木の集計が、画面には最上層しか出ていなくても信用できるのは、これが理由でもある。

  • Baseline Left the Render Path
  • Sort, Insert, Re-assign
  • No More ListIndexes Not Found
  • Committed Per Batch
v2.3.0 <wcs-ssr>

A snapshot of data, not of derivations

What if serializing a page never ran a getter?

An SSR snapshot used to evaluate the state object’s own enumerable getters — a { get count() { … } } written in the object literal — and it evaluated them with the raw object as this, outside the proxy. A path getter therefore serialized as null, and a getter calling $getAll threw and took the whole page’s server render down with it. Snapshots now carry data only. Derived values are recomputed on the client from the same definition, which is where they were always going to be recomputed anyway, so the rendered HTML is unchanged. The one thing to check: a consumer that reached into the snapshot JSON for a getter’s value should read the data it derives from instead.

SSRのスナップショットは、stateオブジェクト自身の列挙可能なgetter — オブジェクトリテラルに書かれた{ get count() { … } } — を評価していた。しかもプロキシの外で、生のオブジェクトをthisとして評価していた。そのためパスgetterはnullとして直列化され、$getAllを呼ぶgetterは例外を投げてページ全体のサーバーレンダリングを道連れにした。スナップショットはいまデータだけを運ぶ。派生値は同じ定義からクライアントで再計算される — どのみち再計算される場所だ — ので、出力されるHTMLは変わらない。確認すべき点は1つ: スナップショットのJSONからgetterの値を取り出していた利用側は、その導出元のデータを読むように変えること。

  • Getters No Longer Evaluated
  • Path Getter Was null
  • $getAll Took the Page Down
  • Recomputed on the Client
v2.3.0 wcs/getter-depth-exceeded

Deep is not circular

What if the error told you which of the two it was?

Exceeding the 128-frame address stack was always reported as a possible circular dependency, even for a straight chain that never visited an address twice. The two are now told apart by address identity: a real cycle stays wcs/getter-cycle, and data that is simply that deep is wcs/getter-depth-exceeded. For a recursive walk the depth check trips first, at 128 wildcard levels, naming the anchor, the depth reached and the path it was building — and nothing is truncated on the way, because a partial aggregate would be a wrong number reported as a right one. Two more edges close alongside: $129, $0 and $01 used to fall through to ordinary property resolution and read as undefined, and now throw (wcs/index-param-range); a $getAll whose indexes is not an array names the argument and the two valid forms instead of a raw TypeError. The linter also reads a substitution-free template literal as a literal path, so $getAll(`items.*.price`, [0]) is checked like a quoted one — which may surface new diagnostics on existing pages.

128フレームのアドレススタックを超えたとき、たとえ同じアドレスを二度と訪れない一直線の連鎖であっても、報告は常に「循環依存の可能性」だった。いまはアドレスの同一性で両者が区別される: 本物の循環はwcs/getter-cycleのまま、単にそれだけ深いデータはwcs/getter-depth-exceeded。再帰的な走査では深さ検査が先に、ワイルドカード128段で作動し、アンカー・到達した深さ・構築中だったパスを名指しする。途中で打ち切られるものは何も無い。部分的な集計は、正しい数のふりをした間違った数だからだ。周辺の穴も2つ塞がった: $129・$0・$01は通常のプロパティ解決に落ちてundefinedと読まれていたが、いまは投げる(wcs/index-param-range)。indexesが配列でない$getAllは、生のTypeErrorではなく引数名と2つの有効な形を告げる。linterは置換の無いテンプレートリテラルもリテラルなパスとして読むので、$getAll(`items.*.price`, [0])は引用符付きと同じく検査される — 既存ページに新しい指摘が出ることがある。

  • Cycle or Depth, By Identity
  • Nothing Truncated
  • $0 / $129 Throw Now
  • Template Literals Linted

The Core Insight

The only contract is a path string

No hooks. No imports. No glue code.

フックなし。インポートなし。グルーコードなし。

In every existing framework, the component is where UI meets state. Even with external stores, you still write glue code inside the component to pull state in. State and UI always couple through JavaScript.

wcstack takes a different path. Literally. The only contract between UI and state is a path string — user.name, cart.items.*.subtotal, cart.total. The component's JavaScript doesn't contain a single line that references state. The HTML alone describes every data dependency — the same idea as a REST URL: a simple string contract, no shared code.

State   ← "user.name" →  UI          Path binds the two layers
Comp A  ← "cart.total" → Comp B      Mounted path crosses components
Loop    ← "items.*" →    Template    Wildcard abstracts the index

UIと状態を結ぶ唯一の契約はパス文字列。UIを作り直しても状態に触れなくていい。状態をリファクタリングしてもDOMに触れなくていい。HTMLを読めばすべてが分かる。

One protocol behind them all: wc-bindable

index.html State 
<wcs-state>
  <script type="module">
    export default {
      taxRate: 0.1,
      cart: {
        items: [
          { name: "Widget", price: 500, quantity: 2 },
          { name: "Gadget", price: 1200, quantity: 1 }
        ]
      },
      removeItem(event, index) {
        this["cart.items"] = this["cart.items"].toSpliced(index, 1);
      },
      get "cart.items.*.subtotal"() {
        return this["cart.items.*.price"] * this["cart.items.*.quantity"];
      },
      get "cart.total"() {
        return this.$getAll("cart.items.*.subtotal", [])
          .reduce((a, b) => a + b, 0);
      },
      get "cart.grandTotal"() {
        return this["cart.total"] * (1 + this.taxRate);
      }
    };
  </script>
</wcs-state>

<template data-wcs="for: cart.items">
  <div>
    {{ .name }} &times;
    <input type="number" data-wcs="value: .quantity">
    = <span data-wcs="textContent: .subtotal|locale"></span>
    <button data-wcs="onclick: removeItem">Delete</button>
  </div>
</template>
<p>Grand Total: <span data-wcs="textContent: cart.grandTotal|locale(ja-JP)"></span></p>

Constraints

Rules of the Game

This project follows five strict constraints. They're what make it interesting.

5つの厳格な制約。これが面白さの源泉。

1

Single CDN import

One <script> tag. That's it. No npm, no bundler, no config.

scriptタグ1つ。npm不要、バンドラー不要、設定不要。

2

Features as custom tags

Everything is a custom element. If it can't be expressed as <wcs-something>, it doesn't belong here.

すべてはカスタム要素。<wcs-something>で表現できなければ、ここには属さない。

3

Initial load = tag definitions only

The script just registers custom elements. No initialization code, no bootstrap ritual.

スクリプトはカスタム要素を登録するだけ。初期化コードもブートストラップ儀式も不要。

4

Respect HTML semantics

Expressions live in data-* attributes and text nodes — places HTML already allows extension. The DOM structure and semantics stay intact.

式はdata-*属性とテキストノードに配置 — HTMLが拡張を許可する場所のみ。DOM構造とセマンティクスはそのまま。

5

Latest ECMAScript

We actively adopt cutting-edge JS features. No transpiling to ES5. This is the future, after all.

最新のJS機能を積極採用。ES5へのトランスパイルなし。未来のプロジェクトだから。

These rules sound simple. They're not. Respecting HTML semantics means you need to deeply understand where the spec allows extension — and where it doesn't. Building everything as custom tags means solving lifecycle, ordering, and communication within the Custom Elements spec. No dependencies means every algorithm is yours to write. And it all has to feel like it could be a browser built-in.

シンプルに聞こえるルールだが、実際は違う。HTMLセマンティクスを尊重するなら、仕様が拡張を許す場所と許さない場所を深く理解する必要がある。すべてをカスタムタグで構築するなら、Custom Elementsの仕様の中でライフサイクル・順序・通信を解決しなければならない。依存ゼロなら、あらゆるアルゴリズムを自分で書く。そしてそのすべてが「ブラウザ組み込みかもしれない」と感じさせなければならない。

Quick Start

One package, one script tag.

Pick only the scoped packages you need. Element packages ship an /auto entry.

必要なスコープ付きパッケージだけを選ぶ。要素パッケージは/autoエントリを持つ。

index.html CDN via esm.run

     storage + autoloader pre-linked, one SRI hash covering all of it -->
<script type="module" src="https://esm.run/wcstack/auto"></script>
