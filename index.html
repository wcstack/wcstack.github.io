What's New

Shipped in v3.0.0 → v3.3.0

3.0 reads a binding as written, or refuses it by name — and the core of @wcstack/state is split from its features. Forms that 2.x rounded off silently — a second #, a value after else:, an unterminated quote — now fail with [wcs/binding-syntax], and forms whose intent is clear are read the way they are written: done|eq(true) matches a boolean, join('; ') keeps its semicolon, an undefined caption removes alt instead of writing "undefined". There is no compatibility layer: 2.6 named every one of these forms as wcs/v3-migration, so upgrade to 2.6.1, clear those warnings, then move to 3.0 — the migration table lists each form with what to write instead. @wcstack/state and /auto still carry every feature, so a page that does not opt into the split entries loads as before. The changes are all in @wcstack/state and its tooling; every other package moves to 3.0.0 only to keep the lockstep version. v3.1.0 follows with two additions: a mount= volume can take a root path under a name of its own (state.taxRate: settings.taxRate), in the vocabulary a component’s partial mount already used, and a leading dot binds a property whose name starts with on (.online: isOnline) instead of listening for an event. v3.2.0 gives names that read as the wrong operation their canonical spelling — upper, toFixed, $dependOn, $renderedCallback, $stream — with the old names kept as aliases through 3.x, and adds coalesce and padEnd. v3.3.0 is a quality pass over all of it: five clean-slate reviews raised 137 findings and 116 are fixed — mostly forms that failed silently, from a for row that rendered nothing to a server that stopped answering — while six forms that 3.1 and 3.2 accepted, each already broken at run time, are now refused by name. The rest of 3.0 — $resolve by argument count, readonly proxies and #ro mounts that refuse writes, rows created 18.7 % faster — is in the migration table and Performance.

3.0はバインディングを書かれたとおりに読むか、名指しで拒む — そして@wcstack/stateのコアを機能から切り離す。2.xが黙って丸めていた書き方 — 2つ目の#、else:の後ろの値、閉じていない引用符 — は[wcs/binding-syntax]で失敗し、意図の明らかな書き方は書かれたとおりに読まれる: done|eq(true)は真偽値に一致し、join('; ')はセミコロンを保ち、undefinedのキャプションは"undefined"を書く代わりにaltを取り除く。互換層は無い: 2.6がこれらの書き方をすべてwcs/v3-migrationとして名指ししてきたので、2.6.1に上げて警告を消し、それから3.0へ移る — 書き方ごとの書き換え先は移行表にある。@wcstack/stateと/autoは今もすべての機能を載せているので、分割エントリを選ばないページは以前どおりに読み込まれる。変更はすべて@wcstack/stateとそのツールの中にあり、他のパッケージはロックステップのバージョンを揃えるためだけに3.0.0になる。v3.1.0は2つの追加で続く: mount=のボリュームがルートのパスを自分の名前で受け取れるようになり(state.taxRate: settings.taxRate)、語彙はコンポーネントの部分マウントがすでに使っていたものと同じだ。そして先頭のドットは、onで始まる名前のプロパティを、イベントを待ち受ける代わりにプロパティとしてバインドする(.online: isOnline)。v3.2.0は違う操作に読める名前に正規の綴りを与え — upper・toFixed・$dependOn・$renderedCallback・$stream — 旧名は3.xの間は別名として残し、coalesceとpadEndを加える。v3.3.0はそのすべての品質パスだ: まっさらな状態から始めた5回のレビューが137件を挙げ、116件を直した — 大半は黙って失敗していた書き方で、何も描かないforの行から応答しなくなるサーバーまである — そして3.1と3.2が受け付けていた6つの書き方は、どれも実行時にはすでに壊れていたもので、いまは名指しで拒まれる。3.0の残り — 引数の個数で決まる$resolve、書き込みを拒むreadonlyのプロキシと#roマウント、18.7 %速くなった行の生成 — は移行表とPerformanceにある。

v3.3.0 defaults('00:00'): .startTime

Silent failures, named

What if every binding that did nothing said so where you wrote it?

3.3 is a quality pass over everything 3.0, 3.1 and 3.2 introduced: five reviews, each from a clean slate, raised 137 findings, and 116 are fixed here. Most were forms that failed silently. A for row whose binding carried a quoted : — value|defaults('00:00'): .startTime — rendered zero rows while lint and the editor stayed green, because the row expander still split on raw delimiters. if: 0 rendered neither branch, so an else: never appeared. n|toFixed(2)upper dropped upper, x|upper painted UNDEFINED into the page, createdAt|date(ja-JP) failed an arity check it should have passed, and .online: — 3.1’s own fix for on-prefixed names — still subscribed to a "line" event. All of those now work as written. A few forms 3.1 and 3.2 accepted are refused by name instead, which is why this is a minor: .state:, an empty path segment on the right (a., a..b — a leading dot is still the loop shorthand), text after a filter’s closing ), a left side that names no property, a $stream entry colliding with a state method, and a path over 512 segments. Each was already broken at run time; now it says so.

3.3は3.0・3.1・3.2が持ち込んだものすべての品質パスだ: 毎回まっさらな状態から始めた5回のレビューが137件の指摘を挙げ、そのうち116件をここで直した。大半は黙って失敗していた書き方だ。フィルタ引数の引用符の中に:を含むforの行 — value|defaults('00:00'): .startTime — は1行も描画しなかった。行の展開器がまだ生の区切り文字で分割していたからで、lintとエディタは緑のままだった。if: 0はどちらの枝も描かず、else:は現れなかった。n|toFixed(2)upperはupperを落とし、x|upperはページにUNDEFINEDと描き、createdAt|date(ja-JP)は通るべきアリティ検査に落ち、.online: — onで始まる名前への3.1自身の対策 — はまだ"line"イベントを購読していた。どれもいまは書いたとおりに動く。逆に3.1と3.2が受け付けていたいくつかの書き方は名指しで拒まれるようになり、これがパッチではなくマイナーである理由だ: .state:、右辺の空のパス区間(a.・a..b — 先頭のドットは今もループの省略記法)、フィルタの閉じ)の後ろの文字、プロパティを名指ししない左辺、stateのメソッドと衝突する$streamのエントリ、そして512区間を超えるパス。どれも実行時にはすでに壊れていた。いまはそう告げる。

v3.3.0 renderToString({ timeoutMs })

One bad page, not a dead server

What if a page that never became ready could not take every later render down with it?

renderToString swaps globalThis, so renders run one at a time behind a mutex released in a finally. A page that never became ready never reached it — and a volume loading from an inline <script type="module"> was such a page — so every later render on the process hung forever, and an invalid url could leak the mutex the same way. 3.3 closes both doors and adds a deadline, RenderOptions.timeoutMs (default 30,000 ms, 0 disables; Infinity means no limit instead of inverting into an immediate timeout), shared with the cleanup so the worst case is the limit plus one second. A server that renders many pages also stops mixing them: the <wcs-ssr> snapshot carries only this document’s templates and hydration props — before, a later page could carry an earlier request’s for rows — and the ledgers are reset after each render instead of growing for the life of the process. On the client, {{ }} inside a for / if survives hydration instead of going permanently empty, a falsy 0 / false is no longer dropped from server textContent, and hydration is linear again: 3,200 rows from 1,207 ms to 108 ms.

renderToStringはglobalThisを差し替えるので、描画はfinallyで解放されるミューテックスの後ろで1つずつ走る。準備が整わないページはそのfinallyに届かず — インラインの<script type="module">から読み込むボリュームがまさにそうだった — そのプロセスの以降の描画がすべて永久に止まった。不正なurlも同じようにミューテックスを漏らし得た。3.3は両方の扉を閉じ、期限RenderOptions.timeoutMsを加える(既定30,000 ms、0で無効。Infinityは即時タイムアウトに化けず「制限なし」になる)。期限は後始末と共有されるので、最悪でも期限プラス1秒だ。多くのページを描くサーバーは、ページを混ぜなくもなった: <wcs-ssr>のスナップショットはこの文書のテンプレートとハイドレーション用プロパティだけを運ぶ — 以前は後のページが前のリクエストのforの行を運び得た — そして台帳はプロセスの寿命のあいだ育ち続けず、描画ごとにリセットされる。クライアント側では、for / ifの中の{{ }}がハイドレーション後に永久に空になることはもう無く、サーバーのtextContentから偽の0 / falseが落ちることも無く、ハイドレーションは再び線形になった: 3,200行で1,207 msから108 msへ。

  • 30 s Deadline by Default
  • No Leak Between Requests
  • {{ }} Survives Hydration
  • 3,200 Rows: 1,207 → 108 ms
v3.3.0 this.$eq("selectedId", 2)

Scopes that mean their own paths

What if a call inside a component always read the component’s own state?

A mounted component and a volume translated $getAll / $setAll / $resolve / $postUpdate onto their own paths, but passed $eq / $eqPath / $eqIndex and $dependOn straight through — so inside <wcs-state mount="cart">, this.$eq("selectedId", 2) compared against the root’s selectedId. All of them now resolve in the scope they are called in. Keyed selection closed two more holes: a getter derived from a keyed getter no longer goes stale, and $postUpdate after an in-place mutation reaches the keyed rows. Class-based state keeps its prototype accessors — class Cart { get total() {…} } as a volume or a bind-component no longer loses total without a word. A deep partial mount (state.a.b: outer.b) no longer makes the component’s sibling keys public, and a component’s own method wins over a partial mount of the same name again. Four behaviour changes come with it, all named in the changelog: the scope-relative keyed calls above, Token.emit delivering to the remaining subscribers when one throws (it no longer rethrows to the emitter), a class getter winning over a host key of the same name inside its component, and a volume declaring $watch on a page without features/temporal reporting [wcs/feature-not-installed] instead of working by accident.

マウントされたコンポーネントとボリュームは$getAll / $setAll / $resolve / $postUpdateを自分のパスへ翻訳していたが、$eq / $eqPath / $eqIndexと$dependOnは素通しにしていた — だから<wcs-state mount="cart">の中のthis.$eq("selectedId", 2)はルートのselectedIdと比べていた。いまはどれも呼ばれたスコープで解決される。鍵付き選択はさらに2つの穴を塞いだ: 鍵付きgetterから導いたgetterがもう古いままにならず、その場の変更の後の$postUpdateが鍵付きの行に届く。クラスで書いたstateはプロトタイプのアクセサを保つ — ボリュームやbind-componentとしてのclass Cart { get total() {…} }が、黙ってtotalを失うことはもう無い。深い部分マウント(state.a.b: outer.b)はコンポーネントの兄弟キーを公開してしまわなくなり、コンポーネント自身のメソッドは同名の部分マウントに再び勝つ。挙動の変更が4つ付いてくる。どれもchangelogに名指しされている: 上のスコープ相対の鍵付き呼び出し、購読者の1つがthrowしても残りに配るToken.emit(発行元へ再throwしなくなった)、コンポーネントの中では同名のホストのキーに勝つクラスのgetter、そしてfeatures/temporalの無いページで$watchを宣言したボリュームが、たまたま動く代わりに[wcs/feature-not-installed]を報告すること。

  • Keyed Calls Resolve in Scope
  • Derived Keyed Getters Stay Fresh
  • Class Accessors Kept
  • Token.emit Reaches Everyone
v3.2.0 upper · toFixed · $stream

Names that say what they do

What if every name read as the operation it performs?

Some names read as the wrong operation, or were abbreviated away from JavaScript’s own. 3.2 gives them canonical names and keeps the old ones as aliases. Filters: inc / dec → add / sub, fix → toFixed, uc / lc / cap → upper / lower / capitalize, rep / rev → repeat / reverse, pad → padStart, and null → nullIfEmpty, which is what it always did. Proxy APIs: $trackDependency / $untrackDependency → $dependOn / $untracked — the old pair read as inverses of each other, and they are not. Declaration keys: $updatedCallback → $renderedCallback, because it observes applied bindings, not every update, and $streams → $stream, singular like $watch and $scan. The old names work the same through 3.x and are removed in 4.0: the filter registry resolves an old name to the canonical implementation and arity, and an old key is moved onto the canonical one once, when the state enters the runtime — declaring both spellings is [wcs/declaration-alias]. Lint and the VS Code extension flag each old name as wcs/name-alias at info with the canonical one; the runtime warns only in the last 3.x minor.

違う操作に読める名前や、JavaScript自身の名前から省略されすぎた名前がある。3.2はそれらに正規の名前を与え、古い名前を別名として残す。フィルタ: inc / dec → add / sub、fix → toFixed、uc / lc / cap → upper / lower / capitalize、rep / rev → repeat / reverse、pad → padStart、そしてnull → nullIfEmpty — 実際にずっとしてきたことの名前だ。プロキシAPI: $trackDependency / $untrackDependency → $dependOn / $untracked — 旧名の2つは互いの逆に読めるが、そうではない。宣言キー: $updatedCallback → $renderedCallback(見ているのはすべての更新ではなく適用されたバインディングだから)、$streams → $stream($watchや$scanと同じ単数形)。旧名は3.xの間同じに動き、4.0で取り除かれる: フィルタのレジストリは旧名を正規の実装とアリティに解決し、旧キーはstateがランタイムに入るときに一度だけ正規のキーへ移される — 両方の綴りの宣言は[wcs/declaration-alias]だ。lintとVS Code拡張は旧名ごとに正規の名前を添えてwcs/name-aliasをinfoで出す。ランタイムが警告するのは3.xの最後のマイナーだけだ。

  • Old Names Work Through 3.x
  • Removed in 4.0
  • Both Spellings Refused
  • wcs/name-alias at Info
v3.2.0 count|coalesce(0)

Zero is a value

What if a fallback replaced only what is actually missing?

defaults(v) replaces every falsy value — right for a name that may be empty, wrong for a count that may be 0: count|defaults(…) overwrites a real zero. coalesce(v) is the ?? of filters: it replaces only null / undefined, so 0, false and "" stay. padEnd(n, c?) joins padStart and pads the end, with a space by default, for fixed-width codes and columns. That makes 48 built-in filters. One fix rides along: add / sub (inc / dec) require their argument, as documented — the arity table said it was optional, so lint let a bare inc through and the runtime then failed without a code. It now fails as [wcs/filter-arity], the same code and bounds in the editor and on the page. Like the new names, the new filters exist from 3.2: on a page pinned to 3.1 or earlier, keep the old spellings.

defaults(v)はあらゆる偽の値を置き換える — 空かもしれない名前には正しく、0かもしれない件数には誤りだ: count|defaults(…)は本物のゼロを上書きしてしまう。coalesce(v)はフィルタ版の??で、null / undefinedだけを置き換えるので、0・false・""は残る。padEnd(n, c?)はpadStartの対として末尾を埋め、既定は空白 — 固定幅のコードや列のためのものだ。これで組み込みフィルタは48個になる。修正が1つ同乗する: add / sub(inc / dec)は文書どおり引数を必須とする — アリティ表が省略可能としていたため、lintは引数の無いincを通し、ランタイムはその後コード無しで失敗していた。いまは[wcs/filter-arity]で失敗し、エディタでもページでも同じコード、同じ範囲だ。新しい名前と同じく、新しいフィルタも3.2からのもの: 3.1以前に固定したページでは古い綴りのままにすること。

  • Only null / undefined Replaced
  • padEnd Beside padStart
  • 48 Built-in Filters
  • add / sub Arity Enforced
v3.1.0 state.taxRate: settings.taxRate

A volume that asks for what it needs

What if a volume could read the root’s settings without knowing where they live?

A mount= volume sees only its own subtree, so a cart module that needed the root’s tax rate had no declared way to reach it — components could take state.x: path from the host, volumes had no equivalent, and a data-wcs on the volume element failed to apply as a write to a missing state property. 3.1 gives volumes the injection point components already had, in the same vocabulary as a partial mount: <wcs-state mount="cart" src="./cart.js" data-wcs="state.taxRate: settings.taxRate">. Inside cart.js — getters, methods, $watch, $listKeys and the lifecycle callbacks — this.taxRate reads and writes the root’s settings.taxRate, with the dependency recorded, so get total() follows a rate change and $updatedCallback sees it under the inner name. The name exists only inside the volume’s code: the page keeps reading settings.taxRate, and the tree gains no cart.taxRate. The injection wins over a data key of the same name, #ro makes it read-only for the volume ([wcs/mount-readonly]), and the target is one static path with no filters — a malformed injection is [wcs/mount-path-invalid], reported before the volume loads.

mount=のボリュームが見るのは自分の部分木だけなので、ルートの税率が要るカートのモジュールには、それに届く宣言的な手段が無かった — コンポーネントはホストからstate.x: pathを受け取れたが、ボリュームには相当するものが無く、ボリューム要素のdata-wcsは、存在しないstateプロパティへの書き込みとして適用に失敗していた。3.1はコンポーネントがすでに持っていた注入点をボリュームにも与える。語彙は部分マウントと同じだ: <wcs-state mount="cart" src="./cart.js" data-wcs="state.taxRate: settings.taxRate">。cart.jsの中 — getter・メソッド・$watch・$listKeys・ライフサイクル — ではthis.taxRateがルートのsettings.taxRateを読み書きし、依存も記録されるので、get total()は税率の変化に追従し、$updatedCallbackは内側の名前でそれを受け取る。この名前が存在するのはボリュームのコードの中だけで、ページはsettings.taxRateを読み続け、木にcart.taxRateは生えない。注入は同名のデータキーに勝ち、#roはボリュームにとって読み取り専用にし([wcs/mount-readonly])、対象はフィルタ無しの静的なパス1つ — 形の崩れた注入はボリュームの読み込み前に[wcs/mount-path-invalid]として報告される。

  • The Partial-Mount Vocabulary
  • Tracked Like Any Read
  • #ro for Read-Only
  • Checked Before the Volume Loads
v3.1.0 .online: isOnline

A property named on…

What if a property whose name starts with on could still be bound as a property?

A binding name that starts with on makes an event binding — that is what makes onclick: save work. It also meant online: isOnline listened for a "line" event and never reached the element’s online property, and once on <wcs-timer> could not be bound at all. 3.1 adds an explicit property form: a leading dot binds the property by name, and is never an event — <my-status data-wcs=".online: isOnline; onclick: refresh">. In every other way it is the undotted binding: .value: is two-way, and modifiers and input filters apply. A namespace word after the dot (.class, .attr, .style, .command, .eventToken) or an empty name is rejected with [wcs/binding-syntax]. The leading dot used to fail at apply time, so no working page changes. The VS Code extension adds wcs/on-prefixed-member: a tag member whose name starts with on, bound without the dot, is flagged with the fix.

onで始まるバインディング名はイベントバインディングになる — onclick: saveが動くのはそのためだ。だがそれは、online: isOnlineが"line"イベントを待ち受けて要素のonlineプロパティに決して届かないことも意味し、<wcs-timer>のonceはそもそもバインドできなかった。3.1は明示的なプロパティの形を加える: 先頭のドットはプロパティを名前でバインドし、決してイベントにならない — <my-status data-wcs=".online: isOnline; onclick: refresh">。それ以外はドットの無いバインディングとまったく同じで、.value:は双方向、修飾子も入力フィルタも効く。ドットの後ろの名前空間の語(.class・.attr・.style・.command・.eventToken)や空の名前は[wcs/binding-syntax]で拒まれる。先頭のドットはこれまで適用時に失敗していたので、動いているページが変わることはない。VS Code拡張はwcs/on-prefixed-memberを加える: onで始まるタグのメンバーをドット無しでバインドすると、直し方つきで指摘する。

  • A Leading Dot Is Never an Event
  • Otherwise the Same Binding
  • Namespace Words Rejected
  • Flagged in the Editor
v3.0.0 wcs/binding-syntax

Refused by name

What if a malformed binding failed where you wrote it, instead of doing something plausible?

The 2.x parser answered broken input with a guess. value#ro#wo: kept ro and dropped the rest, else: x dropped x, a modifier on for / if / elseif / else / ... turned the keyword into a plain property binding, and an unterminated quote in filter arguments was closed for you. 3.0 rejects each of them with [wcs/binding-syntax] — write value#ro,wo:, else:, the bare keyword, the closed quote — and an empty filter (x|, x||y) moves to the same code. A filter given more or fewer arguments than it accepts now fails with [wcs/filter-arity] when the bindings are planned, instead of ignoring the extras. The other half is what used to break and now simply works: ; between bindings and | between filters split only outside quotes, so tags|join('; ') and parts|join(' | ') mean what they say, and resolved filters are cached by the structure of their arguments — slice('1,2') and slice(1,2) no longer share an entry. @wcstack/lint and the VS Code extension report wcs/binding-syntax at error with the canonical parser’s own judgement, so the editor and the page cannot disagree; the 2.6 wcs/v3-migration notice has done its job and is gone.

2.xのパーサは壊れた入力に推測で答えていた。value#ro#wo:はroを残して残りを捨て、else: xはxを捨て、for / if / elseif / else / ...に付いた修飾子はキーワードを普通のプロパティバインディングに変え、フィルタ引数の閉じていない引用符は勝手に閉じられた。3.0はそのどれも[wcs/binding-syntax]で拒む — value#ro,wo:、else:、キーワードだけ、閉じた引用符と書くこと — そして空のフィルタ(x|、x||y)も同じコードに移る。受け付ける数より多い・少ない引数を渡されたフィルタは、余りを無視する代わりに、バインディングの計画時に[wcs/filter-arity]で失敗する。もう半分は、これまで壊れていて、いまは素直に動くものだ: バインディング間の;とフィルタ間の|は引用符の外でだけ区切るので、tags|join('; ')もparts|join(' | ')も書いたとおりに動く。解決済みのフィルタは引数の構造でキャッシュされ、slice('1,2')とslice(1,2)が1つのエントリを共有することはもう無い。@wcstack/lintとVS Code拡張は正規のパーサ自身の判定でwcs/binding-syntaxをerrorとして報告するので、エディタとページの言い分が食い違うことはない。2.6のwcs/v3-migrationは役目を終えて取り除かれた。

  • No Silent Round-Offs
  • ; and | Inside Quotes
  • Filter Arity at Plan Time
  • Lint Uses the Same Parser
v3.0.0 installFeatures([...])

Only the features you use

What if a page that never folds a stream never loaded the code that does?

@wcstack/state/core holds the binding engine — data-wcs, for / if, path getters, events, command and event tokens. Everything else is a feature you add with installFeatures([...]): features/temporal ($watch, $scan, $streams), scopes (bind-component, mount=, DCC), recursion, ssr, formats (the formatting filters — the core answers only not), devtools and diagnostics (the development-time path warnings). The core alone is about 52 KB gzip, and every entry shares one core chunk. A missing feature does not fail quietly: a declaration that needs one throws [wcs/feature-not-installed], naming the entry to import. @wcstack/state/define gives defineState and the types with no runtime at all. Load the split form from jsDelivr’s plain, version-pinned /npm/ paths or through a bundler — never through esm.run, whose re-bundling would give every entry its own engine. @wcstack/state and /auto install every feature and stay the recommended way in: a page that uses them all is smaller as one file.

@wcstack/state/coreはバインディングエンジン — data-wcs、for / if、パスgetter、イベント、コマンドトークンとイベントトークン — を持つ。それ以外はすべてinstallFeatures([...])で足す機能だ: features/temporal($watch・$scan・$streams)、scopes(bind-component・mount=・DCC)、recursion、ssr、formats(書式フィルタ — コアが答えるのはnotだけ)、devtools、diagnostics(開発時のパス警告)。コアだけなら約52 KB gzipで、どのエントリも1つのコアチャンクを共有する。機能が欠けていても黙っては失敗しない: それを要る宣言は[wcs/feature-not-installed]をthrowし、importすべきエントリを名指しする。@wcstack/state/defineはランタイムを一切持たずにdefineStateと型を与える。分割形はjsDelivrの素の、バージョン固定した/npm/パスかバンドラから読み込み — esm.runからは決して読まない。その再バンドルは各エントリに別々のエンジンを持たせてしまう。@wcstack/stateと/autoはすべての機能を組み込み、今も推奨の入口だ: 全部を使うページなら1ファイルのほうが小さい。

The Core Insight

The only contract is a path string

No hooks. No imports. No glue code.

フックなし。インポートなし。グルーコードなし。

In every existing framework, the component is where UI meets state. Even with external stores, you still write glue code inside the component to pull state in. State and UI always couple through JavaScript.

wcstack takes a different path. Literally. The only contract between UI and state is a path string — user.name, cart.items.*.subtotal, cart.total. The component's JavaScript doesn't contain a single line that references state. The HTML alone describes every data dependency — the same idea as a REST URL: a simple string contract, no shared code.

State   ← "user.name" →  UI          Path binds the two layers
Comp A  ← "cart.total" → Comp B      Mounted path crosses components
Loop    ← "items.*" →    Template    Wildcard abstracts the index

UIと状態を結ぶ唯一の契約はパス文字列。UIを作り直しても状態に触れなくていい。状態をリファクタリングしてもDOMに触れなくていい。HTMLを読めばすべてが分かる。

index.html State 
<wcs-state>
  <script type="module">
    export default {
      taxRate: 0.1,
      cart: {
        items: [
          { name: "Widget", price: 500, quantity: 2 },
          { name: "Gadget", price: 1200, quantity: 1 }
        ]
      },
      removeItem(event, index) {
        this["cart.items"] = this["cart.items"].toSpliced(index, 1);
      },
      get "cart.items.*.subtotal"() {
        return this["cart.items.*.price"] * this["cart.items.*.quantity"];
      },
      get "cart.total"() {
        return this.$getAll("cart.items.*.subtotal", [])
          .reduce((a, b) => a + b, 0);
      },
      get "cart.grandTotal"() {
        return this["cart.total"] * (1 + this.taxRate);
      }
    };
  </script>
</wcs-state>

<template data-wcs="for: cart.items">
  <div>
    {{ .name }} &times;
    <input type="number" data-wcs="value: .quantity">
    = <span data-wcs="textContent: .subtotal|locale"></span>
    <button data-wcs="onclick: removeItem">Delete</button>
  </div>
</template>
<p>Grand Total: <span data-wcs="textContent: cart.grandTotal|locale(ja-JP)"></span></p>

Constraints

Rules of the Game

This project follows five strict constraints. They're what make it interesting.

5つの厳格な制約。これが面白さの源泉。

1

Single CDN import

One <script> tag. That's it. No npm, no bundler, no config.

scriptタグ1つ。npm不要、バンドラー不要、設定不要。

2

Features as custom tags

Everything is a custom element. If it can't be expressed as <wcs-something>, it doesn't belong here.

すべてはカスタム要素。<wcs-something>で表現できなければ、ここには属さない。

3

Initial load = tag definitions only

The script just registers custom elements. No initialization code, no bootstrap ritual.

スクリプトはカスタム要素を登録するだけ。初期化コードもブートストラップ儀式も不要。

4

Respect HTML semantics

Expressions live in data-* attributes and text nodes — places HTML already allows extension. The DOM structure and semantics stay intact.

式はdata-*属性とテキストノードに配置 — HTMLが拡張を許可する場所のみ。DOM構造とセマンティクスはそのまま。

5

Latest ECMAScript

We actively adopt cutting-edge JS features. No transpiling to ES5. This is the future, after all.

最新のJS機能を積極採用。ES5へのトランスパイルなし。未来のプロジェクトだから。

These rules sound simple. They're not. Respecting HTML semantics means you need to deeply understand where the spec allows extension — and where it doesn't. Building everything as custom tags means solving lifecycle, ordering, and communication within the Custom Elements spec. No dependencies means every algorithm is yours to write. And it all has to feel like it could be a browser built-in.

シンプルに聞こえるルールだが、実際は違う。HTMLセマンティクスを尊重するなら、仕様が拡張を許す場所と許さない場所を深く理解する必要がある。すべてをカスタムタグで構築するなら、Custom Elementsの仕様の中でライフサイクル・順序・通信を解決しなければならない。依存ゼロなら、あらゆるアルゴリズムを自分で書く。そしてそのすべてが「ブラウザ組み込みかもしれない」と感じさせなければならない。
